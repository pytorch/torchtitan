SGLangEngine runs KDA, keeping replay state in SGLang's slot

In batch-invariant mode, one KDA layer of the Kimi K3 debug model keeps this state for one request after a 150-token prompt.
SGLang's usual KDA state the replay state, added to the slot by this PR tokens not seen yet
Before (#5818): SGLangEngine raises an error for KDA layers.
This PR: SGLang's slot also stores the replay state.
SGLang's radix cache copies every entry, so the next turn resumes the unfinished chunk too.
SGLang's logprobs match the trainer's bit for bit, Kimi K3 debug model on 1 GB300.
Without the replay state, logprobs differ by up to 3.7e-2.
The replay state costs 1.25x the memory of the recurrent state.
