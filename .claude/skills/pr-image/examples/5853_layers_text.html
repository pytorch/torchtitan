SGLangEngine's default prefill CUDA graphs now include attention

Both panels show one small prefill step of Qwen3-0.6B at TP 1, for one new 300-token prompt.
runs inside a CUDA graph runs eagerly, with CPU work on every call option not taken
Before: the default cuda_graph="breakable" runs attention outside the graph.
So every prefill step pays about 7-8 ms of CPU, however few tokens it has.
This PR: the new default cuda_graph="full" also captures attention.
server_kwargs["cuda_graph_config"] = { "prefill": {"backend": "full", "full_prefill_max_req": max_num_seqs}}
The graph gets one request slot per running request.
So attention costs no eager CPU time.
Not taken: SGLang's default of 32 request slots.
A batch with more requests than slots runs eagerly.
So 256 prompts of 100 tokens took 0.51 s, slower than breakable graphs (0.39 s).
A stream of 256 requests, one new per step, now takes about 2.0 s instead of 5.1-5.4 s (Qwen3-0.6B, TP 2, 2 GB300s).
vLLM takes 2.1-2.2 s on the same setup.
Cost: GDN and KDA models now raise an error with the default.
